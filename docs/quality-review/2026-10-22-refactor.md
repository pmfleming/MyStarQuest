## Findings and changes

### Timestamp conversion was unsafe

Calendar history accepted an arbitrary object's `toDate` function and immediately treated the result as a Date. A malformed result could throw during history rendering. Lens reported five blocking unsafe-call, assignment, return, and member-access findings here.

The converter now narrows the callable to an unknown-returning function and validates its result before reading it as a Date. Invalid converted timestamps are ignored; numeric timestamps, real Dates, Firestore-style converters, stored task dates, and child time zones retain their existing behavior. Regression cases cover null, strings, objects, and invalid Dates returned by converters. All five blockers are gone.

### Mutation hooks assumed a ready storage scope

Chore, test, and reward mutations repeatedly asserted that `storageKey` existed after checking only the signed-in user. During child-scope loading, those conditions can differ.

The collection boundary now exposes a writable scope only for an authenticated user, and mutations check the scope directly. Rewards use the same readiness rule. This removes the non-null assertions while preserving authentication checks. A reset regression verifies that no Firestore write occurs while the child scope is unavailable.

`updateUserDocument` now owns the common choice between legacy Firestore updates and native/shared queues. Tests, rewards, and coalesced document updates reuse it. Test creation still uses a transaction for online defaults and creates missing native defaults before patching them. Activity resets still use their separate atomic activity path. Regression coverage exercises all three document-persistence routes, in addition to failed-reset rollback and retry.

### Offline subscription and projection logic repeated decisions

The runtime repeatedly passed the same error handlers and registered the same unsubscribe pattern. Its local `watch` helper now owns both alongside the connection lifecycle. Legacy-history prefixes and operation-ID deduplication remain explicit at each subscription. Cache snapshots still cannot erase durable data; server snapshots retain that authority.

Shared progress projection resolves generation and revision once, handles reset state together, and reuses the existing activity merge operation. Acknowledgement looks up the pending operation once. Store mutation checks initialization explicitly instead of asserting it.

`projectedSharedProgress` falls from **23 to 16 cognitive complexity** and **18 to 12 cyclomatic complexity**. Offline, shared-progress, emulator, and browser tests preserve replay, reset generation, revocation, history, and duplicate-award behavior.

### Calendar rendering and action factories repeated presentation rules

Calendar rows and star counts now have local components. Both summary and entry stars use the same sign and accessibility-label rules. Icon and fallback-title choices use small lookup tables. `CalendarActivityHistory` falls from **33 to 19 cognitive complexity** and **16 to 12 cyclomatic complexity**; the extracted components are included in the project totals below.

Action factories now pass their shared configuration through once. Setup, active, and completed handlers still select the same behavior; dinner retains its timer-dependent bite action, and utility actions retain their reset/delete labels and exit behavior. Two thin utility factories were removed. The module shrinks by 48 lines without changing its consumer API.

Place-value layout applies the tens-specific styles together, reducing its layout selector's cognitive and cyclomatic scores by 3 each. The total calculator uses the existing typed list of all six places instead of asserting the type of object keys.

### Task types and shared validation duplicated contracts

Test variants now share one discriminated-union construction. Writable task field types derive from the explicit snapshot schema keys, excluding identity, category, task type, and creation metadata; the schema's arbitrary passthrough keys are not admitted. This removes 48 lines of repeated declarations while retaining variant-specific fields and narrowing.

Functions reuses its integer validator for sequence and progress-version boundaries and selects activity-value validation without nested branches. `parseOperation` falls from **26 to 22 cognitive complexity** and **17 to 13 cyclomatic complexity**. Tests retain the existing permission, timestamp, fractional-value, and field-limit cases and add unsafe-number/version boundaries. The activity-value helper's own estimated effort increases slightly; the Functions total decreases.

Physical source, including tests, CSS, scripts, and Java: **47,790 → 47,787 (-3 lines)**. Production code loses 129 lines; regression tests add 126. Generated reports and artwork are excluded from this count. This is a small net size reduction, not a large reduction of the whole application.

Complexity and effort sum callable signals. Effort is a static estimate, not measured engineering time. Locality and leverage totals sum module risk scores, where lower is better; they are comparison aids, not official project-wide grades. The frontend's cyclomatic total is unchanged; the combined reduction comes from Functions. Some individual callable scores and the count of high-risk records increase as responsibilities move.

The leverage-risk improvement comes mainly from removing unsafe assertions and validating scope readiness. Actual reuse improves through shared persistence routing, activity merging, and action configuration. The locality-risk reduction comes from direct regression-test association with the shared mutation helper; it does not establish lower production import distance or measured coverage. Subscription lifecycle concerns also now sit together in the runtime.

All clone detectors reported zero groups before and after, so there is no numerical clone reduction to claim. The changes remove conceptual duplication that did not meet those detectors' thresholds. The remaining same-purpose candidate, `storageKeyForChild` versus `childStorageKey`, serves two different responsibilities: selecting legacy/shared storage and encoding a shared namespace. These remain separate.

## Remaining review findings

- **39 layer warnings:** largely composition and cross-layer UI/hooks/data imports. There are no detected dependency cycles. Moving files or introducing barrels solely to reduce path-based scores would obscure ownership without resolving a demonstrated problem.
- **9 accessibility-tool warnings:** six concern `aria-description` support in the installed analyzer; three concern interactive semantics. These need focused accessibility review. Accessible descriptions were not removed to silence the tool.
- **11 package-resolution warnings:** the root cleanup scan sees Functions imports whose dependencies belong to the separate Functions package. Its own build and audit pass. Deployment entry points, migration scripts, and CI tools also appear among cleanup candidates, so they were not deleted based on reachability alone.
- **Remaining hotspots:** offline `enqueue` retains cognitive complexity 28; the Time Explorer orchestration hook remains the largest estimated-effort callable. Animal-session lifecycle, school-calendar refresh, and weather precedence were reviewed but retain distinct behavior and existing regression coverage. Further changes should address a concrete ownership or correctness issue rather than simply splitting callables.
- Vite still warns about a large bundle chunk. This work makes no claim of runtime speedup, smaller bundles, complete accessibility compliance, or measured coverage improvement.
