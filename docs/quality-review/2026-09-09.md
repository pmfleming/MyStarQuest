# Quality Lens review and refactor — 9 September 2026

The refactor removes unused application paths and shares activity behavior while preserving the current routes, stored-document semantics, artwork, and scoring flows. The same frontend analysis scope now contains **549 fewer source lines**, **31 fewer cognitive-complexity points**, **53 fewer cyclomatic-complexity points**, and **two fewer clone groups**.

## Tool and measurement scope

- Tool: [ts-react-quality-lens](https://github.com/pmfleming/ts-react-quality-lens), version **0.3.0**, GitHub HEAD **986c6fd9cc82627866156ba0cf22cb1504ab8587**, verified before starting. The existing sibling checkout was older; this review used an isolated checkout under `tmp/quality-lens-latest`.
- Project baseline: **8684c4cd4d183e8cd88a214bf1a5767407d242db**; the working tree was clean before analysis.
- Frontend: all 167 TypeScript/TSX source modules under `src`, using the existing root Lens configuration, `tsconfig.app.json`, installed dependencies, and the same rules and exclusions before and after. Removing one page and adding one shared component leaves the module count unchanged.
- Backend: both Cloud Functions source modules, analyzed separately with their own compiler configuration. A reusable config is now in `functions/ts-react-quality-lens.config.json`.
- Full measurement covered hotspots, clones, escape hatches, types, typed lint, React/accessibility, dependency graph, cleanup, locality, leverage, test discovery/execution, and architecture. Package checks are inapplicable to these private applications. Runtime profiling and security scanner reports were not supplied; those measurements provide no runtime/security assurance.

Raw frontend results are in `target/analysis`; backend results are in `target/functions-analysis`. The [comparison JSON](2026-09-09-comparison.json) retains both runs' summaries, source provenance, aggregation definitions through its metric names, and individual target metrics. The full initial frontend artifacts are also retained locally in `tmp/quality-baseline`.

Source lines sum only file records, excluding tests, JSON catalog data, CSS, generated reports, dependencies, and the separately measured backend. Complexity and effort sum non-file records carrying those signals. These sums are comparison statistics calculated from Lens evidence, not additional official Lens scores. Halstead effort estimates code difficulty; it does not measure developer hours. Locality includes historical churn and co-change, which an uncommitted refactor cannot erase. Test associations and type coverage are not execution coverage.

The improvement is not uniform: deep relative imports increased from 100 to 103 as activity rules moved into the domain module. Arithmetic's component-level Halstead effort increased from 94,659 to 125,489 despite its cognitive/cyclomatic complexity falling. The common feedback implementation reduces duplication and overall effort, but this particular metric is sensitive to changes in vocabulary and JSX props. The report retains this tradeoff rather than treating every extraction as an improvement.

## Changes guided by the findings

1. **Alphabet challenge lifecycle.** `AlphabetTester` now uses `useActivityChallenge` for retries, delayed feedback, completion, and reset. Its Halstead effort falls from 359,276 to 172,085 and its main component shrinks from 250 to 197 lines. Reset/unmount now cancels both delayed result recording and completion through the existing shared timer cleanup. Explicit failed outcomes retain the previous behavior when failure mode is disabled.
2. **Math feedback rendering.** `MathActivityPlayArea` owns themed result icons, feedback animation selection, and retry animation keys for arithmetic, large numbers, and place value. This removes the main cross-file rendering clone. Arithmetic cognitive/cyclomatic complexity falls from 12/11 to 8/8; large numbers falls from 7/7 to 3/4.
3. **Domain dependency direction.** `ActivityResult` and `MAX_ACTIVITY_MISTAKES` now live with the outcome rules in `lib/activityOutcome.ts`. Business logic and the challenge hook no longer import the UI component module for these rules. Challenge-hook reuse increases from three to four inbound consumers, with Lens leverage increasing from 38 to 48. Outcome-rule leverage increases from 36 to 60.
4. **Snapshot parsing.** A fixed list of managed fields replaces eight repeated conditional object spreads. Null and zero remain explicit values; absent fields stay absent. `parseTaskSnapshot` cognitive complexity falls from 16 to 8, cyclomatic complexity from 17 to 9, and effort from 71,714 to 41,541. The unused daily-todo parser and associated unused schemas/guards were removed after checking consumers.
5. **Obsolete management flow.** `ManageTestsPage` had no imports or route registration. The active Tests page already uses default tests. Removing this page also removes its sole-use creation, deletion, and title-draft APIs from `useTests`; default-test persistence, optimistic reconciliation, completion, failure, and reset remain. The hook's effort falls from 725,126 to 600,299.
6. **Public surface cleanup.** Removed unused guards, lookup exports, schema variants, and the redundant default Firebase export. Types and helpers used only inside their own module are now private. No blanket suppression or exclusion was added to improve the numbers.

## Reproduce

From the project root, with the isolated tooling checkout present:

```powershell
node tmp/quality-lens-latest/dist/bin/ts-react-quality-lens.js measure all --config ts-react-quality-lens.config.json
node tmp/quality-lens-latest/dist/bin/ts-react-quality-lens.js measure all --config functions/ts-react-quality-lens.config.json
node tmp/quality-lens-latest/dist/bin/ts-react-quality-lens.js audit --base HEAD --config ts-react-quality-lens.config.json --format markdown
npm run build
npm run lint
npm run test
npm run test:e2e -- --reporter=line
npm --prefix functions run build
```

On a fresh checkout, clone the Lens repository into that tooling directory, check out revision `986c6fd9cc82627866156ba0cf22cb1504ab8587`, run `npm ci` and `npm run build` there first. Check GitHub HEAD before deliberately upgrading; do not compare the old sibling checkout's metrics with this baseline. The frontend config's sibling `$schema` path is only an editor hint; this review used the 0.3.0 CLI's runtime validation.
