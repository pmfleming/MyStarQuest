## Scope and method

The baseline was measured immediately before this refactor, including the existing calendar artwork, calendar caching, performance work and offline queue changes. It is **not** the older committed baseline used by the CI comparison. Both measurements use the same analyzer revision, source roots, compiler configuration, installed dependencies and Git history. No findings were suppressed and no source exclusions were added.

The automated review covers all 242 frontend source files and the backend TypeScript project: complexity, effort, clones, types, typed lint, dependencies, React, accessibility, cleanup, locality and leverage. Manual review concentrated on the highest effort/complexity records, shared card contracts, data subscriptions and mutations, legacy progress migration, calendar scheduling and request deadlines. The Android calendar repository and browser offline worker were also inspected; Lens does not measure Java.

## Remaining review findings

- **High effort remains in large UI hooks/components.** `useAnimalSession`, `DashboardPage` and `StarInfoBox` remain substantial maintenance hotspots. This refactor does not claim to eliminate that debt. Further work should separate actual responsibilities with behavioural coverage, rather than split functions solely to lower a number.
- **Architecture heuristics need interpretation.** The animal-knowledge cycle includes a type-only back-reference; the dependency tool did not confirm a runtime cycle. Layer rules also flag intentional composition-root/provider and calendar catalog dependencies. They remain visible rather than being suppressed or “fixed” with path aliases.
- **Cleanup candidates are not automatically deletable.** Firebase exported handlers, migration/artwork scripts, the offline Playwright configuration and browser fixtures are entry points or manually invoked tools. Static unused reports alone do not justify removing them.
- **The backend daily-reset batch is unbounded.** `resetChildChores` still puts all eligible chores into one Firestore batch. A sufficiently large family dataset needs bounded batching and partial-failure tests. This is retained as a follow-up finding; no production data migration or endpoint removal was attempted.
- **Some typed assertions and accessibility warnings remain.** The animal seed mapping and worker boundary still warrant review. The report is a reduction in risk, not a claim of zero warnings.
- **Performance and coverage limits.** No runtime performance artifact or code-coverage percentage was supplied to Lens. Fewer subscriptions and temporary objects are implementation improvements; this review does not claim a newly measured first-load speedup. Browser offline checks are not a physical-device network test.
