# Quality review and refactor — 14 September 2026

The refactor reduces measured complexity, effort, cloning, and locality/leverage risk in both application and Cloud Functions code. Production code is **227 physical lines shorter**. Added regression tests use those 227 lines, so **production plus test code has no net line reduction**; the requested total-line reduction is only achieved for production code. CI configuration adds two lines, and generated reports are excluded from code counts.

## Implemented changes

- **Task subscriptions:** `useChildTaskCollection` now owns shared user/child/date setup, ephemeral state, resets, and snapshot reconciliation. `useChores` and `useTests` retain their distinct task and attempt semantics. Snapshot handling still gets the current date at delivery time. Together these modules lose 28 Lens lines and approximately 67,900 estimated effort units.
- **Asset loading and task types:** shared required-asset resolution replaces repeated lookup/error handling. Typed Vite globs remove assertions; food/habitat name unions derive from the image maps; task discriminators derive from existing Zod schemas. Season/background helpers retain explicit named properties without asserted record casts.
- **Countdown presentation:** one display-geometry selection replaces repeated illustrated/plain conditional expressions. Cognitive complexity falls from 46 to 30 and cyclomatic complexity from 52 to 36. This module grows 33 lines to make the visual parameters explicit; its benefit is simpler control flow.
- **Day/night backdrop:** color interpolation reuses the existing background-blend traversal and normalization, eliminating duplicate time-stop logic. Cognitive complexity falls from 23 to 14, effort from 154,190 to 81,408, and Lens lines from 215 to 169.
- **Chore rendering:** a typed factory centralizes lazy-renderer Suspense wrappers while inferring each component's props. The preset-renderer module falls from 89 to 29 Lens lines. Unified rendering shares its editable condition and image options and removes unreachable or trivial wrappers.
- **Cloud Functions:** scheduled and manual reset paths share batch preparation while preserving their distinct title rules. Scheduled resets now safely skip malformed non-string titles. Callable ownership validation handles unknown payloads without casts or non-null assertions. Four handler tests cover reset filtering, settings, legacy response shape, authentication, invalid input, and child ownership.
- **CI:** both jobs that run the frontend test suite now install the nested Functions dependencies needed by the new backend handler tests.

The remaining clone is the symmetric event-listener setup/cleanup in `AppErrorBoundary`; preserving visible lifecycle symmetry is preferable to introducing a helper solely to remove that finding.

## Remaining review priorities

1. **Validate timestamp adapters at the storage boundary.** `firestoreTimestampLikeSchema` in `src/data/types.ts` accepts any object, while `choreParser` and `useChildren` optionally invoke `toDate`. An object with a present but non-callable `toDate` can pass validation and then throw. Add an explicit callable check and malformed-storage tests before tightening the shared adapter.
2. **Keep the calendar timeout active through body consumption.** `getSchoolCalendar` clears its timer after response headers, before `response.text()`, and does not clear it in a `finally` block when fetch rejects. A follow-up should cover both rejection cleanup and a stalled response body.
3. **Address accessibility interactions.** Nine static accessibility findings remain, including countdown mouse interactions and controls in `LearningNavigation`, `TrainingPhotoPortrait`, `DragScrollRegion`, and `StarInfoBox`. Verify keyboard behavior and semantics with interaction tests; static counts alone cannot establish accessibility.
4. **Refactor remaining complex state transitions with focused tests.** The largest remaining callable cognitive scores are AnimalTester's `FactCard` (22), weather-store refresh (21), and StandardActionList's `ActionCard` (19). Their interaction, cancellation, and pending/reset behavior needs targeted tests before restructuring. Splitting these solely by file size would provide weak evidence of improvement.
5. **Harden backend input and batch recovery separately.** Dinner values now have honest `unknown` types but retain existing persistence behavior rather than gaining runtime numeric validation. Scheduled resets still process users/children sequentially and lack batch chunking or per-child failure isolation. These warrant explicit schema and recovery behavior tests.

The frontend high-risk hotspot count decreases from 137 to 136, but the React high-risk component heuristic increases from 26 to 27. The repository is therefore improved on the requested aggregate measures, not free of architectural or correctness concerns.

## Reproduction

From the project root, install both package trees with `npm ci` and `npm ci --prefix functions`. Run `npm run lint`, `npm run test`, `npm run build`, `npm run build --prefix functions`, and `npm run test:e2e -- --workers=1 --reporter=line` with the Playwright browsers available. Run `node scripts/quality-gate.mjs HEAD` for the repository's configured audit workflow. To reproduce this report's deltas, measure the stated baseline commit and refactored tree separately using the stated Lens revision and unchanged frontend/backend configurations; comparing only committed artifacts uses a different baseline.
