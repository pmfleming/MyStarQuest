## Scope and measurement

The baseline is a fresh measurement of the working tree immediately before this refactor, including the previous Time Explorer persistence, theme artwork and deletion-confirmation changes. Comparisons against the older committed artifacts would mix those features with this refactor, so this report uses the fresh baseline instead.

Lens reviewed the frontend and Firebase functions separately for complexity, effort, duplication, types, typed lint, React hooks, accessibility, cleanup, dependencies, locality and leverage. Manual review followed the highest-ranked records through animal sessions and collection loading, shared action controls, globe parsing/rendering, stored profile selection, calendar loading, task mutations, offline synchronization and backend daily resets. Compiler and dependency review included consumers of the changed modules.

Both before/after pairs use the same analyzer revision, configuration, dependencies and Git history, with matching analysis identities. No source exclusions, finding suppressions, policy changes or dependency upgrades were used to improve the measurements. The whole-project audit runs in the existing quality-gate script's temporary checkout, preserving history and current source while avoiding a diff-limited audit scope.

## Findings addressed

| Finding                                                                                                                                                            | Change                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The menu's child-management navigation discarded a potentially rejecting promise, producing the baseline's typed-lint blocker.                                     | Return the navigation result to the existing asynchronous button boundary so it owns promise settlement.                                                                                                                                                                                        |
| Globe topology repeated its shape in TypeScript definitions and a chain of hand-written runtime guards.                                                            | One Zod Mini schema now supplies validation and inferred types. Decoding and geometry construction remain local to the existing module. Malformed, non-finite coordinates and fractional arc references fail at the boundary.                                                                   |
| Time Explorer independently assembled the globe state for React updates and hand dragging, and calculated its background blend twice.                              | Both rendering paths use one scene projection, and the backdrop color consumes the already calculated blend. The callback ref explicitly permits its initial empty state.                                                                                                                       |
| City switching used the last React clock snapshot, which can lag the visible seconds, and did not carry the date across midnight.                                  | Read the exact clock time at the interaction and update the destination city's date and time together. The regression verifies the globe's solar instant stays unchanged.                                                                                                                       |
| The largest effort hotspot mixed collection loading/order/choice generation with round feedback, progression and persistence.                                      | A private `useAnimalCatalog` hook owns the catalog concern. It stays in the existing animal-session module, so no new public helper layer or distant dependencies are introduced. Round timing, selection limits, Teenie Ping identity filtering, and reset cancellation retain their behavior. |
| Animal data extensions imported types from the catalog that imported them, forming a type-dependency cycle; seed iteration required an unsafe narrowing assertion. | Shared animal types live in a small data-only contract. Seed keys are checked against the display-category contract, with an explicit invariant check when projecting entries. This removes a structural cycle, not a runtime initialization failure.                                           |
| Saved child selection used nested ad hoc field checks.                                                                                                             | A local schema preserves valid fields independently and defaults malformed fields to null. Storage exceptions still leave the app usable.                                                                                                                                                       |
| Action utilities relied on inline literal assertions, and the shared action button retained a second, unused link/button rendering path.                           | Utility choices have an explicit contract; the unused navigation branch is removed. Existing callers continue using the same asynchronous button behavior. Delete/reset confirmation artwork and keyboard focus behavior are preserved.                                                         |
| An unused top-icon component and its styles, plus a superseded calendar-loading function and TTL, added maintenance surface.                                       | Removed them after checking references. The active calendar store retains its caching, native support, deadline, retry and subscription behavior. Its cancellation handler no longer needs a non-null assertion. The internally used time-format helper remains private.                        |

## Validation and practical limits

- Latest-Lens whole-project gate: **warn**, complete evidence, **0 blockers**, **48 nonblocking warnings**, with no configured or baseline suppressions.
- Full configured Vitest suite: **passed**. The backend's independent Lens config disables test execution; its function tests run through the root suite, so the separate backend artifact correctly does not claim a second executed suite.
- ESLint: **passed**, no warnings. Application TypeScript/production build and Firebase functions build: **passed**.
- Both production Chromium offline tests: **passed** — editing a saved family's chore with the network disabled, and reopening offline with sign-in recovery after reconnecting.
- Targeted regression groups passed, including both illustrated themes, all-off panel restoration, custom weather, city/date/time restoration, topology decoding and malformed inputs, partially damaged profile preferences, collection switching, delayed completion cancellation, and shared delete/reset controls.

The production build still reports its existing large-chunk advisory. This refactor does not claim bundle-wide size reductions.

The real bundled world map produces identical decoded output before and after the topology change: one land feature and 242 country features, with equal SHA-256 hashes of the complete decoded collections. This stronger validator has a small runtime cost: a local warm ten-run sample averaged about **6.0 ms before / 12.7 ms after**, and the separately downloaded worker grows from **2.65 KB to 20.93 KB** uncompressed. Zod Mini avoids the roughly 71 KB worker produced by the full Zod API. The timing sample is a local comparison, not a cross-device performance benchmark; no startup-speed improvement is claimed.

The remaining Lens warnings include layer-boundary heuristics, accessibility findings and cleanup classifications. Some cleanup findings involve externally invoked scripts or separately declared function dependencies and are not safe deletion candidates. The large dashboard, calendar store, activity mutation hooks and drag-scroll component remain effort hotspots. Their concurrency and persistence paths are covered by existing tests, but the static metrics do not prove complete behavioral coverage. Accessibility warnings on SVG interaction surfaces, custom navigation and older ARIA rule support still need focused review; none were suppressed here.

This refactor does not deploy Firebase functions or rebuild/install the Android application. Backend compilation and the root suite cover the functions; production Chromium checks cover the saved-family offline flows. No physical-device verification was performed.
