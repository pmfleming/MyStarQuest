## Findings and changes

### Offline synchronization

The original `flush` mixed queue coordination, transport rejection, local acknowledgement, permission failures, and retry scheduling. Its cognitive complexity was 46. `sendPending` now owns transport outcomes and acknowledgement; `handleFailure` owns status and retry scheduling; `flush` coordinates the durable queue.

The distinction between a rejected server operation and a failed local acknowledgement remains explicit: a local failure after commit retains the operation for replay with its original ID. A new regression exercises that boundary. Shared-child revocation, terminal rejection, stopped/offline state, exponential backoff, and attention status retain their behavior.

`flush` cognitive complexity falls from 46 to 8; the new send/failure helpers score 11 and 8. The comparison also includes those helpers, rather than claiming only the extraction's per-function gain.

### Shared-child transactions

The original mutation callback scored 141 cognitive complexity. Document editing, reward redemption, activity progress, balance updates, and history-envelope construction now have named, private helpers in the same service file. Authorization, scoped entity resolution, receipt lookup, and dispatch remain inside the original Firestore transaction. All helper reads and writes use that transaction.

This preserves migration boundaries, admin-only settings/resets, tombstones, consumption protection, stale-generation rejection, replay receipts, star accounting, and history payloads. The largest resulting mutation helper, `updateActivity`, scores 51. The service still has a substantial state machine; it was not split further merely to shrink individual function scores.

The backend tradeoff is explicit: cognitive complexity falls 46, while cyclomatic complexity rises 6, estimated effort rises 95,523, and source grows 32 lines. Named boundaries and a typed transaction context improve reviewability, but are not free in these metrics. Combined project totals still improve.

### Story lifecycle and motion

Air and cleaning scenes reuse the existing story-layer lifecycle for image decoding, readiness, cancellation, visibility, and disposal. Scene-specific builders and animation settings remain local. The shared lifecycle exposes readiness, stop, and visibility callbacks instead of duplicating complete controllers.

Animation visibility handling is shared and does not restart finished animations. Transition listeners share an AbortController for cleanup. Underwater images reuse the decorative image constructor while retaining the underwater scene's persistent-character and crossfade behavior. Empty image sources remain unset.

Opening and closing motion use normalized endpoint states for geometry, opacity, snapshot opacity, shadow, and scale. Interrupted closing still uses the captured current state. `animateStorySurface` cognitive complexity falls from 29 to 15. No artwork was generated or changed.

### Calendar and card presentation

Calendar period/selection/illustration styles now live in scoped CSS; invariant layout uses existing utilities. Theme colors remain at the component boundary. Cell selection exposes `aria-pressed`. The day-cell callback falls from cognitive complexity 39 to 20.

Day, week, and month cells were compared with the saved baseline at 320px and 600px in both themes. All 12 combinations matched the checked computed styles and geometry, with no horizontal overflow. The current Teenie week screenshot was visually inspected. These checks compare styles; they are not a claim of exhaustive pixel equivalence for every event/date.

Card animation and interaction CSS is imported statically instead of injected through a mounting effect. CardShell supplies the existing dimension tokens as typed custom properties. Exit behavior, reset-confirmation sizing, reduced motion, and animation timings are retained.

### Reuse and data resolution

Sharing-friend selection reuses the existing shuffle implementation. Llama/alpaca records share their common habitat/food seed while retaining their distinct abilities. Calendar history builds its definition indices once and resolves declared or legacy activity collections consistently, preserving test-first legacy lookup and unknown-activity fallback. Typed asset glob declarations replace unnecessary assertions.

Five clone groups disappear. Two small groups remain: shared-control prop wiring in AnimalTester/SpellingTester, and animation completion/cancellation handling in photo moments/transitions. Their differing owners and lifecycles do not justify another shared abstraction just to obtain a zero.

The Functions dependencies are declared in their own package; those root-level cleanup findings need package-aware interpretation. Cleanup candidates were not deleted solely because a tool marked them unused: fixture/build/package entrypoints need separate confirmation. No runtime-performance, bundle-size, or measured-coverage gain is claimed. Vite's existing large-chunk warning remains.

Validation used the installed Node 24.11/npm 11.7 environment, below the package's declared Node/npm versions. The successful builds and tests are evidence for this environment, not a replacement for CI on the declared toolchain. Browser verification was Chromium with fixtures; no deployment, Android installation, or full manual account walkthrough was performed.
