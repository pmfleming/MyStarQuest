## Findings and changes

### Progress and scoring rules had multiple definitions

Client task types and Functions policy repeated the completed-field mapping. The action hook, card renderer, and server also maintained overlapping water/toilet score calculations. These definitions could drift when adding a task or changing its score.

The shared protocol now owns completed-field names and the water/toilet score rule. The frontend retains its compile-time check that each completed field belongs to the matching task variant. `calculateTaskStars` serves both persistence and card presentation; it preserves ordinary tasks' configured rewards and water/toilet defaults. Eight regression cases verify the expected score for every water/toilet combination on both sides of the write boundary.

Stored numeric revision conversion is shared across offline projection, local transactions, and Functions. It preserves existing numeric-string and missing-value behavior; incoming operation validation still rejects coercible strings. Regression cases verify that older and unversioned snapshots cannot replace a newer numeric or string revision. `projectedSharedProgress` drops from 12 to 9 cyclomatic complexity and from 16 to 13 cognitive complexity. Server `awardFor` drops from 8 to 5 cyclomatic and 11 to 4 cognitive complexity; the new shared helper is counted in the totals.

### Card controls passed redundant state through several layers

The list passed style resolvers through every card and separately forwarded utility labels, icons, flags, and variants. Primary visibility was already part of the primary action; edit visibility could already be expressed by the available edit handler.

Button styling now belongs to the button renderer. Utility presentation travels as one typed object. Redundant primary/edit visibility flags and the unused style-resolver type are removed. A row key is resolved once and reused for React identity and inline editing. Async action errors, pending controls, reset/delete confirmation, focus restoration, and failed-delete rollback retain their existing behavior.

### Dinner timing and general chore actions shared one large closure

The delayed final bite, timer start/expiry, and reset-version guard now live together in a local `useDinnerActions` hook. General completion and failure actions share the existing persistence boundary. `calculateTaskStars` removes a second score selector from the card state module, alongside two unnecessary forwarding helpers.

The old action hook's estimated effort was 318,400.49. The remaining hook is 39,400.69 and the dinner hook is 170,710.30. The project totals include both hooks and all their recorded helpers. The regression suite exercises a reset during the final-bite delay, duplicate awards, and persisted completion.

### Story controls repeated navigation and relied on unsafe assertions

The main reader and companion comic share keyboard page selection in the existing story-presentation module. Home/End, Page Up/Down, arrows, and Space retain bounded navigation; input and button keyboard behavior stays with the focused control.

Story animation reads viewport dimensions through one local helper and passes the captured dimensions into geometry calculations. Open and reverse-close fades share their keyframe construction. CSS custom properties use explicitly typed objects, pointer targets are narrowed with `instanceof`, and cloned nodes are checked before HTMLElement operations. All four typed-lint warnings disappear.

Browser regressions cover fullscreen geometry, image proportions, scrubbing, bounded keyboard navigation, reduced motion, interrupted opening, reverse closing, focus restoration, and phone gestures. Existing Teenieping and princess artwork is preserved.

### Task parsing used an incomplete switch contract

Variant construction now uses an exhaustive typed lookup that keeps each discriminator beside the fields selected for that variant. Adding a task type requires a corresponding entry. The parser still returns only the active variant's fields and preserves snapshot validation, legacy names, defaults, null resets, and custom titles.

This reduces the selector's cyclomatic complexity from 9 to 1. Its individual effort estimate increases from 9,350 to 15,740.98, and it constructs a small lookup per parsed document. This is a tradeoff for the exhaustive contract; aggregate effort decreases across the project.

### Weather duplicated subscription bookkeeping

Weather now reuses the existing `snapshotStore` for snapshot identity and listener publication. Subscriber count lets weather retain its own request lifecycle, including the microtask grace period for StrictMode resubscription. Cache expiry, independent cities, stalled-request retry, and late-response rejection remain covered by the existing weather tests.

## Remaining review findings

- **40 inferred layer warnings:** app composition, feature types, UI helpers, and core modules cross the tool's default layers. Some reflect composition boundaries; others identify coupling worth addressing, particularly task types depending on theme options and Time Explorer controls depending on feature types. No layers or thresholds were changed to silence them.
- **11 dependency warnings:** the root Knip adapter also scans Functions and tests importing Functions dependencies. Those dependencies are declared in the Functions package. These need package-aware interpretation rather than duplicate root dependencies.
- **8 accessibility warnings:** seven concern `aria-description` on button roles; one concerns dialog keyboard interaction in AppMenu. The refactor does not change those controls or suppress the findings.
- **Cleanup candidates require context:** Firebase exports, migrations, standalone comic entry points, browser fixtures, and operational scripts are used through tooling or external entry points. They were retained. The same-purpose storage-key candidate also remains: one function selects legacy versus shared storage, while the other serializes an already-resolved child scope.

Large data catalogues and complex activity layouts remain high in the size rankings. Further splitting solely to lower file-size scores would add indirection without necessarily reducing decisions or maintenance work.
