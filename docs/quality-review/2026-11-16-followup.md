# Project review and refactor follow-up — 16 November 2026

The review found useful consolidation in avatar controls, activity setup, story transitions, calendar calculations and number generation. The refactor also separates shared activity state decisions from transaction writes and fixes a blocking history-aggregation type error. All requested aggregate metrics improve, although the complexity and size reductions are modest.

## Refactoring decisions

- **Avatar ownership and reuse:** `ChildAvatar.tsx` now contains both display and selection. Its sole-use picker module was removed, accounting for the 23-point locality reduction. `Carousel` renders image options directly, eliminating duplicated image construction in avatar and theme selection and a redundant descriptor input.
- **Activity setup:** the shared setup controls own the established 1–9 problem limit. Alphabet, animal, spelling and math callers no longer repeat the bounds. Specialized labels, star limits and difficulty controls remain with their activities.
- **Animation reuse:** a shared completion helper handles rejected/cancelled animation groups, while each scene retains its generation guard. Normal page turns apply identical geometry and transforms to the outgoing image and its frozen layered snapshot in one loop. Photo scenes reuse decorative image creation. Browser tests cover interrupted navigation, replay, reduced motion, missing layers and cleanup.
- **Safer scenery and snapshots:** habitat scenery uses explicitly typed image pairs rather than six non-null assertions. DOM snapshots are checked before HTMLElement-specific operations, and transition clones use Element APIs. These changes, plus typed calendar CSS variables, account for the 164-point leverage-risk reduction. This is safer shared-module implementation, not a measured increase in runtime performance.
- **Calendar calculations:** the grid derives row count from its existing date slots, reuses the history selector and simplifies period-dependent columns. Month height, selected-day width, period transitions and both themes remain covered by browser assertions.
- **Number generation:** common ranges and sampling replace repeated progression formulas. All four difficulties produced identical results in 3,936 seeded before/after comparisons, including out-of-range indices and single-problem sessions. Existing problem-generation and activity tests pass.
- **Sharing progress:** `nextActivityState` owns reset, prior completion, failure and award-state decisions; `updateActivity` retains authorization, stale-generation/revision checks, transaction ordering, history and consumption writes. Its cognitive complexity falls 51 → 30. Migration uses a guard for non-current task completions and computes its timezone once.
- **History typing and test isolation:** typed entry aggregation replaces an `Object.assign` spread that lost its result type. A clean-source audit also exposed two existing tests importing unused Firebase services. Scroll-header and child-access tests now mock those unused dependencies while retaining their real scroll/subscription assertions.
