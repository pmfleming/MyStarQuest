## Changes

### Resolve actions once at the card boundary

The old descriptor adapter called a row's action getter separately for its label, accessibility label, image, disabled state, visibility, variant, and click handler. The card then resolved those field callbacks again. This obscured where a row's action was chosen and repeated the same computation.

All four list consumers now pass their row descriptors directly. Each card resolves its primary and utility actions once per render. The shared types describe resolved values, and two adapter/helper modules were removed. Default deletion, an absent custom utility, custom reset, hidden buttons, and disabled buttons remain distinct. Unused `showLabel` fields were removed from this icon-only API; the separate repeat-control label option remains supported.

Utility defaults, confirmation labels, and the action callback are resolved together. Celebration decoration sets visibility and disabled state directly. Focus refs stay on rendered controls to satisfy React's ref rules. Regression tests cover per-row action values, hidden utility actions, cancel focus, confirmation, retained cards, and failed deletion.

### Put clock display state beside clock behavior

`useExplorerClock` now returns a `view` containing its hands, refs, display labels, and controls. The Time Explorer model adds the activity artwork and background to that view. `ClockViewModel` derives the shared fields from the hook instead of repeating their declarations.

This removes repeated wiring from the highest-effort callable while keeping persistence, city selection, date restoration, and globe synchronization intact. The current scheduled activity still supplies the header clock character.

### Keep place-value settings together

Hundreds, tens, and ones now have one settings table for their labels, factors, theme colors, stepper sizes, gaps, and value widths. Three small selection helpers and several repeated conditionals were removed. Responsive and counter-layout behavior remains in the rendering code where it is used.

### Simplify offline replay and validate application startup

Offline replay now selects the target collection/document and checks snapshot acknowledgement before applying the operation. Document replacement, patching, deletion, and star changes retain their separate behavior. Existing persistence and browser tests cover reloads, concurrent tabs, retries, and duplicate-award prevention.

Startup checks that the root element exists before passing it to React, replacing a non-null assertion with an explicit diagnostic. This accounts for the reduction in Lens's leverage-risk total; the larger reuse improvement is the simpler shared action contract.

Physical source totals, including tests: **41,321 → 41,192 lines (-129)**. Production source shrinks by 170 lines; the test changes add a net 41 lines.

Complexity and effort totals sum callable signals. Halstead effort is a static estimate, not measured development time; enclosing and nested callables can overlap. Locality and leverage totals sum module risk scores, where lower is better. These aggregates aid comparison and are not official project-wide Lens grades.

The locality reduction comes from removing two indirection modules. It does not establish a runtime speedup. The leverage reduction comes from removing one unsafe assertion. Useful `as const` declarations remain: this Lens revision includes them among type-assertion risk signals, although they do not bypass type checking.

The clone detector reported zero groups before and after. This refactor removes conceptual duplication in action resolution, clock wiring, and place-value selection without claiming a numerical clone reduction. Physical line counts also include CSS, tests, scripts, and Android Java, so moving code outside TypeScript would not hide it from that comparison. Generated reports and artwork are excluded from physical source counts.

## Remaining findings and limits

- The frontend retains 48 Lens warnings. They include layer heuristics around app composition, hooks, and shared UI types; accessibility findings that need case-by-case review; and root-level Knip warnings about dependencies declared in the separate Functions package. They were not suppressed.
- The Functions audit passes. Its source remains unchanged because the review did not identify a worthwhile behavioral refactor within this scope. Root tests exercise its reset and calendar behavior, and its own TypeScript build passes.
- `ActionCard` cognitive complexity falls from 20 to 18; offline replay falls from 14 to 13. The Time Explorer model's estimated effort falls from 518,253 to 467,835. Some individual callable metrics increase as resolution moves to its owning component; the report presents project totals as well as these local tradeoffs.
- Larger remaining areas include the Time Explorer orchestration hook, animal-session state, chore completion actions, calendar refresh lifecycle, offline enqueue, and weather selection. Splitting these solely to shrink per-function scores would add indirection. Further changes should target a specific ownership or correctness problem with regression coverage.
- Vite still reports a large bundle-chunk warning. This work does not claim bundle-size, runtime-performance, or measured-coverage gains. Browser validation uses isolated fixtures, and installing the APK is not a complete manual phone walkthrough.
