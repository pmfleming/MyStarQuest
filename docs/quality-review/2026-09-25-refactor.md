## Findings and changes

1. **School-event classification mixed a catalog with a branch chain.** A typed, ordered rule table now holds names, patterns, artwork and optional day-off/release-time details. One resolver handles normalization and fallback. Classification cognitive complexity falls from 15 to 3, and cyclomatic complexity from 16 to 4. The original behavior was compared across 96 scenarios, including capitalization, repeated spaces, specific versus broad names, holiday boundaries and unknown titles. Inherited object names such as `constructor` now safely produce an ordinary unknown event instead of being mistaken for a holiday entry.

2. **Chore and reward artwork repeated the same identity information in multiple places.** Each now has one definition list and a Map for lookup. Chore artwork resolves through the existing theme catalog, removing redundant princess-image imports and the separate key guard. Reward option ordering and the legacy `pinkPrincess` alias are preserved. Regression tests cover themed images, legacy keys, invalid/inherited names and exact spelling overlays.

3. **Fraction answers were spread across independent state values and repeated reset sequences.** Selection, recognition choice, replay count and the problem's starting mistake count now form one answer state. One initial value defines a reset. Hint requests are derived from replay count instead of another boolean. The response UI is a separate local component, sharing its feedback container across build and recognition modes. FractionsTester's cognitive complexity falls from 21 to 16; the extracted response measures 4, making the redistribution visible rather than pretending those decisions vanished. Existing tests preserve unlimited retries, hint timing, arbitrary correct piece selection, recognition and restart behavior.

4. **Chore creation duplicated defaults and accepted overly broad schedule patches.** Shared defaults now express the differences between chore types. Unused precomputed icons and single-child layout wrappers are removed. The scheduling control's callback accepts only its two scheduling fields, so the form no longer needs defensive checks for unrelated task fields. Existing titles, star values, school-day defaults, dinner settings and saved document shapes remain unchanged.

5. **Number exercises repeated the operand-row layout.** Both operands now use the same grid-row rendering. Counter adjustment and regrouping logic remain unchanged and the existing 19-counter/99-total regression test passes. This is a small reduction in repeated presentation code, not a new numerical algorithm.

6. **Reward presentation repeated mode-dependent labels and used unchecked style assertions.** Purchase/earned labels and sparkle timing are defined together; custom CSS properties are type-checked through a local style adapter. The rewards page delegates deletion to its existing asynchronous action boundary instead of logging and rethrowing the same error twice. No animation timing or reward transaction behavior was changed.

## Interpretation and remaining priorities

Both source scopes were scanned for complexity, clones, types, dependencies, escape hatches, React health, cleanup and correctness. There are no detected dependency cycles. The frontend full audit is complete with **0 blockers and 48 architecture warnings**; functions are complete with **0 blockers and 0 warnings**. No rules, exclusions, baselines or suppressions were relaxed.

The numerical **locality-risk reduction of 54 comes from direct regression-test associations** for the two artwork modules and the school-event classifier. Definition ownership is simpler, but this score change is not evidence that import distances or historical coupling decreased. The **leverage-risk reduction of 60** comes from removing assertions in chore artwork and replacing fraction/reward CSS assertions with checked types. The Lens treats assertions, including literal assertions, as weak-surface signals; its leverage score is not a runtime reuse or productivity measurement.
