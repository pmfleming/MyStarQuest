# Project review and refactor — 30 October 2026

The review found the clearest opportunities in the new story renderer: duplicated scene lifecycles, a deeply nested transition dispatcher, repeated React effect selection, and repeated page-layout settings. These were refactored without changing the artwork, story order, animation timing or application features.

## Tool and scope

Used **ts-react-quality-lens 0.3.0**, built from [commit 233239b623b67df9c772d7ac3602740fb9de3f12](https://github.com/pmfleming/ts-react-quality-lens/commit/233239b623b67df9c772d7ac3602740fb9de3f12). `git ls-remote` verified that this is still upstream `main` on 30 October. The existing CI pin therefore did not need changing.

Measured the current working tree before editing, including the existing uncommitted comic work. Reviewed the frontend/shared story modules, Firebase Functions and standalone comic entry point. Added a separate comic Lens config so its own source is measured alongside the shared modules already covered by the frontend config. Shared source is counted once in the totals below. Both sides use the same tool revision and measurement settings; exclusions, suppressions and quality thresholds were not relaxed.

The review examined hotspot, clone, type, lint, React/accessibility, dependency, cleanup, correctness, locality and leverage artifacts. It also inspected the scene controllers, transition recipes, story renderer/data, activity UI hotspots, calendar history, offline collection/replay boundaries and server-side operation validation.

## Refactoring decisions

### One lifecycle for CSS scene layers

`storyLayerScene.ts` now owns decorative image creation, image decoding, cancellation generations, visibility pausing, optional entrance timing, and disposal. Ice cream, tidying, satellites, Dingdong's arrival and space flight supply only their scene-specific DOM and assets.

Failed layers still leave the static illustration visible. A late successful or failed image decode cannot replace or clear a newer scene. Entrance observers are disconnected on navigation and disposal, and a disposed controller cannot restart. The shared image helper also serves the cleaning, playground and transition renderers.

The five controllers plus their shared lifecycle shrink from 451 to 295 lines. The image helper serves eight scene/transition consumers while retaining scene-specific coordinates and effects beside their artwork. WAAPI scenes keep their distinct animation ownership; they were not forced into an expansive options framework merely to eliminate the final small clones.

### Transition lifetime and visual recipes have separate responsibilities

The transition player's `play` function now loads the images, selects the recipe and awaits completion through one cancellation path. Dive, castle approach, diamonds, portals, opening doors and birthday lighting have separate local recipe functions. The normal-page recipe was moved beside the other recipes, removing its single-consumer module, duplicate animation-function type and unnecessary parent-element assertion.

`play` drops from **cyclomatic 35 / cognitive 100 / effort 57,990.71** to **13 / 14 / 9,375.54**. Project totals include the extracted recipe functions, so this is not reported as if their complexity disappeared. Keeping the normal recipe with its sole owner accounts for the 18-point locality-risk reduction. The transitions file itself grows; the overall source count falls.

### Select the React scene once

`StoryPageArtwork` resolves a scene factory once instead of repeating four conditional JSX branches and a second selection table. It preserves the special underwater continuity rule and the wait for the requested page's image to decode. CSS custom-property objects use an explicit return type instead of an unsafe assertion. The component's cognitive complexity falls from 25 to 18.

### Keep layout defaults with the story

The story declares the common poster framing, width and aspect ratio once. Each exceptional page retains its explicit dimensions. An evaluated before/after comparison confirmed **all 64 panel objects and all chapter metadata are identical**, including accessibility text, image paths, optional effects and motion values. No assets were regenerated.

### Make the calendar test independent of local credentials

A clean-copy audit exposed an existing calendar-history test dependency on local Firebase settings. The test disabled the offline path but still imported its real transport. It now mocks that unused transport, while retaining the real collection hook and its assertions about child switching, subscription cleanup and subscription failures. The corrected test passes without local Firebase configuration.

## Validation

- Main app, comic and Functions TypeScript/build checks passed. Vite's existing large-chunk warning remains.
- Full main-app Vitest run: **70 files, 183 tests passed**. The new lifecycle tests exercise stale successful/failed decodes, load failure and recovery, page-turn ordering, visibility and disposal.
- Main-app Chromium Playwright: **31 scenarios passed**, including offline behavior, activity layouts, both story sizes, page navigation, failure fallback and animation cleanup.
- Comic Chromium Playwright: **37 scenarios passed**. After the final recipe/data consolidation, all **14 affected transition/sparkle scenarios** passed again. Those include all 64 pages' sparkle coverage, normal page turns, special effects, reduced motion, interrupted navigation and resize cancellation. The open-door transition screenshot was inspected.
- ESLint, changed-file Prettier checks, `git diff --check`, and both quality-summary aggregation tests passed.
- Frontend typed-lint findings fell from **2 to 0**; compiler diagnostics remain **0**, React Hooks findings remain **0**, and dependency cycles remain **0**.
- Final whole-project audits are complete with **zero blockers**: frontend **warn, 59 warnings**; Functions **pass, no warnings**; comic **warn, two tooling/dependency warnings**. Full results are recorded in the companion JSON.

Lens has a fixed 120-second test-command timeout. A successful ordinary two-worker test run took 121.53 seconds, so final audit execution uses `VITEST_MAX_WORKERS=4` locally. The saved source configuration and CI worker settings remain unchanged.

Whole-project audits run in a source copy with the same Git history and a remote named `quality-source`, without `origin/main`, following Lens's documented no-base mode. This avoids mistaking a changed-file audit for a whole-project review and allows the newly added comic config to be audited without an unavailable historical config. Source copies contain no local Firebase settings. Raw measurement totals were checked against the live checkout and match.

## Reproduction

Build the verified Lens checkout, then run `measure all` with each of `ts-react-quality-lens.config.json`, `functions/ts-react-quality-lens.config.json` and `comic/ts-react-quality-lens.config.json`. Use the existing `scripts/quality-summary.mjs` aggregation for the metric table. Archive the baseline before making edits; do not compare these gains against older committed artifacts.

For a complete audit rather than changed-file scope, use the source-copy approach above and `audit --gate all --format markdown` without a base. Set `VITEST_MAX_WORKERS=4` for the frontend audit in this environment. Run the two Playwright configs separately; the Functions and comic Lens configs intentionally do not execute browser tests.
